1. Arquitetura dos alvos dos testes

Tudo roda na mesma máquina, em contêineres Docker. O programa de teste (o dashboard e os experimentos) fala com os dois bancos pelo mesmo módulo de consultas, lib/consultas.js.

Neo4j MySQL, SQL puro (consulta recursiva) MySQL, busca em níveis (laço no programa)

Os mesmos dados nos dois alvos

  1. OpenStreetMapextraído com o OSMnx, uma capital por vez
  2. 2 arquivos CSVintersecoes.csv e estradas.csv
  3. Neo4jneo4j-admin import, mais índices de cidade e tipo
  4. MySQLLOAD DATA INFILE, com chaves e índices do esquema

Os dois bancos recebem exatamente os mesmos arquivos e têm os mesmos totais. Cada estrada de mão dupla vira dois trechos (um em cada sentido) e a de mão única vira um.

2. Como foi feita a busca em níveis

Em SQL puro não dá para parar a consulta recursiva quando ela acha o destino. Por isso fizemos uma segunda versão: o programa conduz a busca, nível a nível, e o MySQL só responde "para onde se vai saindo destas interseções". Aperte Próximo e acompanhe cada ida e volta ao banco.

3. Os três métodos lado a lado

      
O mesmo par de pontos, buscado de três formas. As marcações mostram o que cada método percorre neste grafo de exemplo.

      

        

          
MySQL, SQL puro

          
          

          
WITH RECURSIVE r (node, depth) AS (
  SELECT :origem, 0
  UNION DISTINCT
  SELECT e.destino, r.depth + 1
    FROM r JOIN estrada e ON e.origem = r.node
   WHERE r.depth < :limite
)
SELECT MIN(depth) FROM r WHERE node = :destino

        

        

          
MySQL, busca em níveis

          
          

          
visitados = {origem}; fronteira = [origem]
repita até achar o destino:
  linhas = SQL(fronteira)   -- 1 ida e volta
  novos  = destinos ainda não visitados
  fronteira = novos

-- SQL de cada nível:
SELECT DISTINCT origem, destino
  FROM estrada WHERE origem IN (:fronteira)

        

        

          
Neo4j, shortestPath

          
          

          
MATCH (a:Intersecao {id: $origem}),
      (b:Intersecao {id: $destino})
MATCH p = shortestPath(
  (a)-[:LIGA_A*..150]->(b))
RETURN length(p),
       [n IN nodes(p) | n.id]

        

      

      
Nos experimentos, o Neo4j respondeu em poucos milissegundos em qualquer distância; a busca em níveis cresceu com a distância; e o SQL puro estourou o limite de 30 s com o limite de saltos folgado. As medianas estão no documento das Entregas 3 e 4.
